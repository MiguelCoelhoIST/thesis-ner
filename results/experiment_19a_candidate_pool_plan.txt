Experiment 19a - Real-STJ candidate pool for human validation

Objective
Create a new pool of candidate passages from real Portuguese Supreme Court of Justice (STJ) judgments for later human annotation under the Experiment 19 fine-grained taxonomy.

Why a new benchmark is needed
The expanded taxonomy introduces roles that are not represented in the earlier benchmark. A new independently collected pool is required to evaluate those roles without adapting or contaminating the existing evaluation material.

Frozen previous benchmark
The existing 50-example real-STJ evaluation set remains frozen. It will not be modified, reused as extraction seeds, or included automatically in the new candidate pool.

Candidate discovery
Lexical role anchors are used only to discover passages that may be useful for annotation. A suggested label records which lexical anchor triggered extraction; it is not a gold label and must not be treated as one.

Human validation target
The intended final benchmark contains around 10-12 human-validated examples per fine role. Candidate counts may be larger because ambiguous, duplicate, unsuitable, or incorrectly suggested examples will be rejected during review.

Annotation requirement
Every final label requires manual validation. Candidate extraction must leave label and annotation metadata unset and human_validated=false.

Provenance and privacy
Candidates must come from real STJ judgments. Raw non-anonymized judgments must not be committed. Candidate material must be reviewed for anonymization and suitability before any dataset is committed.

Future splitting
When train, validation, or evaluation splits are later created, examples from the same process must remain in a single split to avoid process-level leakage.

Later stages
This stage performs candidate extraction only. No model is trained and no candidate is accepted as ground truth automatically.

Document-reader review and current support
No existing Word/RTF document-reading or conversion utility was found in src/ or scripts/.
- DOCX: standard-library ZIP/XML reader extracts body paragraphs, text split across runs, table-cell paragraphs, tabs and line breaks in document order. No extra dependency is required. Headers, footers, footnotes, comments, tracked revisions and embedded objects are outside the reader's scope. Images/scans require separate OCR. Inspect representative converted documents before annotation.
- RTF: striprtf decodes RTF control words, Unicode escapes, and ANSI byte escapes using the declared code page (Windows-1252 when absent). Install requirements.txt. Malformed RTF, missing dependencies and decoding failures are reported explicitly.
- DOC: binary legacy Word is not directly supported. Every .doc file is counted and listed as skipped with a pre-conversion reason. Do not rename .doc to .docx. Convert with LibreOffice as described below; encrypted, damaged or image-only documents still require separate attention.
- TXT, TEXT, MD, HTML, HTM: UTF-8/UTF-8-BOM text; HTML is converted to readable text. Other encodings must be converted explicitly to UTF-8. No replacement-character decoding is used.
- JSON/JSONL: existing text/content/body/judgment/document_text fields; JSON process_number metadata is retained when available. Unrecognized containers, empty text and invalid JSON are counted as failures.
- Other formats, including PDF: counted and reported as unsupported. No document is silently dropped from file accounting.

Offsets and source fidelity
Contexts are continuous slices of the extracted document text. Entity offsets always refer to that extracted context and no entity markers are inserted. Word/RTF layout is not preserved as a binary-file character stream; offsets do not refer to bytes or Word character positions. Candidate schema and unvalidated annotation defaults remain unchanged.

Audit and failure behavior
--audit-only reads documents and discovers candidates to measure coverage, without writing candidate text. --audit-json optionally writes counts, relative filenames, reasons and process IDs under the Git-ignored data/raw/ directory; it includes no judgment text. Existing pool and audit paths are never overwritten. Exit status is non-zero when no supported documents can be read or no candidates are found. Partial failures remain visible in the report so coverage can be assessed before extraction.
The audit includes all file extensions, successful file/document counts, failed/skipped reasons, contributing documents, discovered/selected candidate counts by role, distinct normalized process IDs and missing-ID records.

Process diversity and evidence selection
Process IDs are taken from JSON metadata, then text, then recognizable filenames. Stable root IDs group appellate versions and incident suffixes (for example 123/22.1T8ABC-A.P1.S1 under 123/22.1T8ABC). This is deliberately conservative for later split isolation. Original process_number values remain in candidates. When IDs are missing, filenames without extensions are fallback groups and the audit records the uncertainty; identity across unrelated filenames cannot be inferred reliably.
Sampling uses fixed seed 42, gives distinct processes a first turn per role, then applies --max-per-process-role (default 2), with at most 12 selected candidates per process across roles. Duplicate versions are compared within process/role/target groups. Local discovery retains at most 3 candidates per role and 12 overall per document, preferring adjacent anchor/target links.
--hard-share (default 0.25) targets a share of contexts containing multiple person-like mentions or multiple role types. This is a heuristic, not manually assigned difficulty. Process diversity and caps take precedence; the attainable share depends on available candidates. The audit records the actual hard-context count. All role suggestions and evidence preferences require human review.
UNKNOWN has no lexical anchor in this discovery stage; out-of-scope or unsupported target roles can become UNKNOWN only through manual annotation. Additional targeted discovery may be needed to reach its final quota.

Legacy DOC pre-conversion on Windows with LibreOffice installed
Convert each .doc to DOCX in a separate output tree inside the input directory. The original file is retained; the recursive audit will still report it as requiring conversion and will additionally read its DOCX counterpart. Check conversion exit status and existence of each expected output. Preserve directory structure to avoid filename collisions. Do not run this against real data during tooling development.

PowerShell batch procedure:
  $irisRoot = (Resolve-Path 'data/raw/iris').Path
  $officeExe = 'C:\Program Files\LibreOffice\program\soffice.com'
  if (-not (Test-Path -LiteralPath $officeExe)) { throw 'Install LibreOffice or supply its soffice executable path.' }
  $legacyFiles = @(Get-ChildItem -LiteralPath $irisRoot -Recurse -File -Filter '*.doc')
  foreach ($legacyFile in $legacyFiles) {
      $relativeFile = $legacyFile.FullName.Substring($irisRoot.Length).TrimStart([char[]]'\/')
      $relativeFolder = Split-Path -Parent $relativeFile
      $convertedRoot = Join-Path $irisRoot 'converted-docx'
      $convertedFolder = if ($relativeFolder) { Join-Path $convertedRoot $relativeFolder } else { $convertedRoot }
      $expectedDocx = Join-Path $convertedFolder ($legacyFile.BaseName + '.docx')
      if (Test-Path -LiteralPath $expectedDocx) { throw "Conversion output already exists: $expectedDocx" }
      New-Item -ItemType Directory -Path $convertedFolder -Force | Out-Null
      & $officeExe --headless --convert-to docx --outdir $convertedFolder $legacyFile.FullName
      if ($LASTEXITCODE -ne 0 -or -not (Test-Path -LiteralPath $expectedDocx)) { throw "Conversion failed: $relativeFile" }
  }

If LibreOffice is unavailable, use an approved local Word conversion workflow to Save As DOCX and preserve directory/process metadata. Do not upload judgments to online conversion services. Review text extraction quality and reconcile .doc counts with converted outputs before building the candidate pool.
LibreOffice command-line reference: https://help.libreoffice.org/latest/en-GB/text/shared/guide/start_parameters.html?DbPAR=BASIC&System=WIN

NER-based revision v3 (after the first human pilot)
The v2 capitalized-phrase/placeholder heuristics produced organizations, legal codes, road abbreviations and coordinated person names as targets. Those heuristics have been removed from production person detection. All new candidate targets must originate from exact PER spans emitted by the pretrained spaCy model. Role anchors remain discovery hints only.

Local model inspection
- Preferred local path: models/eduardo_extended_model.
- Existing pipeline scripts already use this model and read doc.ents with label_ == 'PER'.
- Stored pipeline: transformer followed by ner; transformer backbone neuralmind/bert-base-portuguese-cased, strided token windows 128/96.
- Actual loaded NER labels: DAT, IDP, LOC, MOR, ORG, PER.
- Available files include config.cfg, meta.json, tokenizer, ner/model, transformer/model and vocab files.
- The installed spaCy 3.8.13 / spacy-transformers 1.4.0 / transformers 4.53.2 environment loads the model. Its saved spaCy compatibility range is >=3.6.1,<3.7.0 and loading emits compatibility/state-dict warnings. Successful loading does not prove unchanged accuracy under the newer libraries. The audit records those warnings, model configuration hash, runtime version and model labels; synthetic integration checks supplement controlled regression tests.
- No new Python dependency is introduced by the NER revision. spaCy and spacy-transformers are already listed in requirements.txt.
- If unavailable or unusable, extraction stops with setup instructions. Restore Eduardo's iris-lfs-storage/model-extended bundle to the local path, or supply --ner-model with a valid local pipeline containing a PER recognizer. No baseline or regex fallback is selected automatically and no model is trained.

Span safeguards and provenance
Only NER-predicted PER spans enter target selection. Conservative rejection rules remove apparent organizations/legal codes, road abbreviations, coordinated/merged spans, invalid offsets and conflicting overlap predictions. These rules can reject valid edge cases, including compound surnames with conjunctions; manual review remains required. They never synthesize a person span or split a merged prediction. Separate people are retained only when NER supplies separate spans. Anonymized placeholders are eligible only if NER recognizes them as PER; this may reduce placeholder recall and must be measured in the audit/pilot.
All former candidate fields are retained. Additional provenance records source_document_id, entity_document_start/end, entity_detection='spacy:PER', and context_per_count. Context offsets select exactly the NER target in an unmodified extracted-text slice; document offsets select it in the extracted full document. Existing source filenames and process identifiers are preserved.

Audit interpretation and coverage
Every one of ARGUIDO, REU, AUTOR, REQUERENTE, RECORRENTE, RECORRIDO, TESTEMUNHA and RELATOR is reported with lexical-anchor occurrences, discovered candidates and selected candidates, including zero counts. No UNKNOWN examples are fabricated.
ner_span_counts reports accepted_per_spans, dropped_false_entities, merged_spans, non_per_predictions, reason-specific drops and window/character counts. 'Accepted' here means passed the automatic span filters, not human-validated. 'Dropped false entities' is a filter counter, not an independently measured NER error rate. Non-PER model predictions are excluded and counted separately. Counts refer to the anchor-window search region, not a census of every entity in every judgment.
Process-root grouping and version deduplication are retained. Role selection now proceeds round-robin so an earlier role cannot consume the entire per-process budget before later roles are considered. Distinct processes are preferred within each role, then globally lower-use processes; caps and deterministic seed 42 remain in force.

Performance for the 388-document corpus
The model is loaded once. Role anchors define local NER search windows, overlapping windows are merged up to 6000 characters, and nlp.pipe batches these windows (default --ner-batch-size 4, n_process=1). No full-document transformer graph is retained and long source documents are not silently truncated to the spaCy maximum length. Window-edge or conflicting entity boundaries are discarded, rather than converted into invented offsets. Use --ner-batch-size 1 if memory is limited. There is no full-corpus timing claim; the new audit records document versus NER input character counts and number of windows to support that measurement.

Outstanding methodological decision: cited proceedings
The thesis must choose and document which task is intended:
1. Mention-level labeling: a role explicitly supported for this person in a cited proceeding may be annotated even when it belongs to another case.
2. Current-case classification: only a role in the judgment's current proceeding is eligible; cited-case-only mentions need a separately agreed exclusion/annotation rule.
The current extraction code does not decide between these definitions. It retains locally discovered PER candidates without assigning gold labels or classifying the proceeding reference. Reviewers should flag citation-dependent cases in their review notes for policy discussion. Do not silently equate a cited-case role with the current-case role, or automatically map such cases to UNKNOWN. Record the supervisors' eventual decision and apply it consistently before a gold benchmark is finalized.

Preservation
The existing v2 candidate pool, human reviews and frozen 50-example evaluation set remain unchanged. No confidential judgment text is added to code, tests, documentation or result files.

Windows performance revision (smoke-test before a full rerun)
The implementation already used bounded windows and nlp.pipe; it did not perform an extra full-document NER pass. The local pipeline contains only transformer and ner, both required. With dense role anchors, however, the union of bounded windows may cover nearly all document text and overlapping portions are still processed. Transformer inference on CPU remains potentially expensive. The previous CLI printed only after the entire corpus finished and buffered output, making progress invisible. Task-manager CPU time is accumulated across threads and does not by itself identify wall time or which stage dominated the interrupted run.

Confirmed avoidable costs and changes
- Anchor regexes were scanned over each full text independently for coverage, window generation and candidate discovery. A single per-document anchor index now serves all three.
- Candidate discovery compared every anchor to all PER spans and repeatedly recounted all context entities. Sorted offset indexes now restrict those searches to relevant ranges without changing eligibility or offsets.
- Conflicting PER detection used all-pairs comparisons. An interval sweep preserves its rejection behavior with lower complexity.
- Process/evidence/hard-context scores were recomputed throughout sampling. They are cached once per candidate; the sampling order and caps are retained.
- Identical NER window strings could be inferred repeatedly across windows or duplicate versions. A bounded in-memory cache (default 128 entries, --window-cache-size 0 to disable across-batch reuse) reuses only exact inputs to the same loaded model. Identical windows within a batch are also inferred once. Every prediction is projected through the requesting document's original window offset. Different overlapping contexts are retained rather than discarded, since changing context may change NER predictions. No cache containing judgment text is written to disk.
- The cache retains all original source IDs and offset provenance; the audit records each document's ner_window_ranges, actual inference count and cache hits. Rejected entities, gold-label policy and human_validated defaults are unchanged.
- Inference remains batched through nlp.pipe with one worker. --cpu-threads defaults to 4; use 0 to retain the environment default. The inspected local default was 6 threads, so extreme thread oversubscription was not established as the cause. A tiny sequential synthetic check measured about 0.12s at 6 threads versus 0.09s at 4; this includes warm-up/order effects and is not a corpus speed benchmark.

Measurements and observability
--progress-seconds defaults to 10. Flushed heartbeat output continues during model loading or a slow NER batch and reports completed documents/total, wall elapsed time, inferred windows, accumulated candidates, and current document size/window count. Frequent internal updates are throttled to avoid flooding the Windows terminal.
--max-documents 5 or 10 selects the first N readable documents in sorted source-file/container order. It does not randomly change with each run. Deferred files/documents are explicitly reported. Container files count by document, not by file. Parsing first plans the limited set, enabling an exact progress denominator; selected text is released after its processing finishes.
The audit stores aggregate phase timings for file parsing, anchor discovery/window planning, NER inference, span filtering, candidate discovery/deduplication/sampling, and model loading. Per-document profiles expose source IDs, sizes, anchor/window counts, cache hits and stage times. File parsing is timed globally because one container can supply multiple documents. total_elapsed_seconds covers processing through final selection; PowerShell timing below includes output writing too.

Synthetic checks on this local environment
- Candidate discovery only, 500 repeated anchors: approximately 0.221s before versus 0.097s after indexing.
- Candidate discovery only, 1000 repeated anchors: approximately 0.682s before versus 0.194s after indexing; both returned 3 capped candidates. These exclude NER and are not estimates for the real corpus.
- An actual-model check on ten identical fabricated short documents passed offset and annotation-default assertions, making one inference and nine exact-window cache hits. This verifies reuse and provenance, not realistic corpus throughput; actual hit rates depend on corpus repetition.
No real judgment contents were processed to obtain these development measurements. The interrupted real-corpus run had no phase profile; its dominant stage must be established from the limited local smoke run rather than asserted retrospectively.

Post-v4 provenance and annotation protocol
The 61-record / 10-reviewed-example pilot is retained as-is. Its results motivate the new protocol in docs/experiment_19a_annotation_protocol.md and the investigation in results/experiment_19a_provenance_report.txt. The earlier unresolved cited-proceeding discussion above is superseded for Experiment 19a by an explicitly mention-level task: supported roles in cited proceedings are eligible, but each role's proceeding scope is recorded. Current-case classification remains a separate task requiring explicit filtering/adjudication.
New candidates distinguish exact decision_id from normalized process_group_id. Header, filename and body-reference evidence remain separate; conflicting exact IDs are not silently reconciled. The legacy process_number field is retained as evidence, while process-level sampling uses the new grouping when available. Unknown/conflicting root groups must be adjudicated before dataset splitting. Related .S1/.S2 decisions belong to the same split group but are not assumed to be the same exact decision.
